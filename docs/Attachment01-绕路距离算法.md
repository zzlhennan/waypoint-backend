# 绕路距离算法说明（DetourCalculator 数学原理）

> 本文解释 `utils/DetourCalculator` 的**计算方法与数学思路**：为什么这样算、公式从哪来、精度够不够。
> 与 PRD `01-需求文档.md` 第 7 节（算法口径）配合看——那边讲流程，这边讲数学。

---

## 1. 要解决的问题

输入：
- **一条折线** `route`：高德返回的驾车路径坐标串，一串经纬度点 `P₀, P₁, …, Pₙ`，相邻点连成线段；
- **一个候选 POI** 坐标 `Q`（比如某家咖啡店的经纬度）。

输出：`Q` 到**整条折线**的最短直线距离（米），即响应里的 `distanceToRouteMeters`。

直觉：用户从 A 骑车到 B 走这条路线，这家咖啡店离"主路"最近有多远？越近越顺路。

---

## 2. 第一步：经纬度不能直接当平面坐标算距离

高德给的是**经纬度**（单位：度），不是米。直接拿 `Δlon`、`Δlat` 算欧氏距离是错的，因为：

- **纬度方向**：地球一圈约 40000 km，跨 360°，所以 1° 纬度 ≈ 111 km（全球基本一致）。
- **经度方向**：经度线在两极收敛，1° 经度的实际长度随纬度变化——赤道上 1° ≈ 111 km，到了纬度 φ 处，1° 经度 = 111 km × cos(φ)。越往北（北京 ≈ 40°N），同样 1° 经度代表的东西距离越短。

所以要先把"度"换算成"米"，再在平面上算距离：

```
dy（米）= Δlat × 111000
dx（米）= Δlon × 111000 × cos(φ)
```

其中 **φ 取这段折线两端的平均纬度** `(lat_a + lat_b) / 2`——路线跨得宽时，用每段自己的平均纬度比用全局平均更准。

> 常数用 `111000` 而非精确的 `111320`：差 0.3%，对"排序哪家最顺路"无影响（所有 POI 同比例缩放）。

---

## 3. 第二步：点到线段的最短距离（核心）

折线由一段段小线段组成。`Q` 到整条折线的距离 = `Q` 到**每一段** `A→B` 的距离中的**最小值**。

关键子问题：**点 Q 到一条线段 AB 的最短距离是多少？**

### 3.1 思路：投影

把 Q 投影到直线 AB 上，投影点为 C。分两种情况：

- **投影落在线段内**（C 在 A、B 之间）→ 最短距离就是 Q 到 C 的垂直距离；
- **投影落在延长线上**（C 在线段外）→ 最短距离退化成 Q 到最近端点（A 或 B）的距离。

```
情况1（垂足在线内）        情况2（垂足在线外）
     Q                          Q
     |                           \
     |                            \
 A---C---B                    A---B  (垂足落在 B 外侧)
 最短 = |QC|                   最短 = |QB|
```

### 3.2 公式（向量投影）

把 A 当作原点，平面米坐标下：

```
向量 AB = (bx, by) = ((b.lon - a.lon)·mPerLon, (b.lat - a.lat)·111000)
向量 AQ = (px, py) = ((q.lon - a.lon)·mPerLon, (q.lat - a.lat)·111000)
```

投影参数 `t` 表示"垂足在线段上的位置比例"（0 = A，1 = B）：

```
        (AQ · AB)        px·bx + py·by
t  =  ─────────────  =  ───────────────
         |AB|²              bx² + by²
```

然后**把 t 钳制到 [0, 1]**：

```
t = max(0, min(1, t))
```

- t 在 [0,1] 内 → 垂足在线段上，用投影距离；
- t < 0 → 垂足在 A 外侧，钳到 0，最短距离退化为 |QA|；
- t > 1 → 垂足在 B 外侧，钳到 1，退化为 |QB|。

钳制这一步，同时解决了"垂足在线内"和"退化为端点"两种情况，一个公式全包住。

垂足 C 的坐标（米）：

```
C = (t·bx, t·by)
```

最终距离：

```
distance = √((px - cx)² + (py - cy)²)
```

---

## 4. 第三步：点到整条折线的距离

折线有 n-1 段，逐段算点到线段距离，取最小：

```
minDistanceMeters(Q, route) = min over each segment ( pointToSegmentMeters(Q, A, B) )
```

边界处理：
- 折线只有 1 个点 → 退化为 Q 到该点的距离；
- 折线为空 → 防御性返回 0（正常流程不会走到这）。

---

## 5. 第四步：沿折线采样（sampleRoute）

为了在路线上"每隔一段距离搜一次周边 POI"，需要把连续的折线离散成**采样点序列**。

### 5.1 采样规则（PRD Q10 决策）

```
采样点 = 起点 + 每 500m 一个插值点 + 终点（强制包含）
```

- **强制含起点、终点**：起终点是用户必然在的位置，那里的店"零绕路"，漏掉就违背"顺路"初衷；
- **每 500m 一个中间点**：沿折线累计弧长，每满 500m 切一刀。

### 5.2 怎么切：累计弧长 + 线性插值

沿折线逐段累计"已经走了多远"（`traveled`）。当某段 `A→B` 跨过了一个采样刻度 `nextSampleAt`（500、1000、1500…），就在这段上**线性插值**出那个点：

```
              (nextSampleAt - traveled)
  t  =  ─────────────────────────────────
              该段长度 segLen

  采样点 = A + t·(B - A)        （经度、纬度分别按 t 插值）
```

一段可能跨过多个刻度（长直线段 + 短间隔），用 `while` 循环把该段内所有刻度都插值出来。

### 5.3 去重

相邻采样点间距小于 0.01m 时视为同一点、合并——避免：
- 短路线（全程 < 500m）：起点和终点被重复采样；
- 插值点恰好落在端点坐标上时产生重复点。

## 6. 精度与误差分析

| 误差来源 | 量级 | 是否影响排序 |
|---|---|---|
| double 浮点运算 | ~1e-10 米 | 否（远小于输入精度） |
| 坐标输入精度（高德 6 位小数） | ~0.1 米 | — |
| 111000 vs 真实 111320 | 0.3% | 否（所有 POI 同比例） |
| 平面投影 vs 地球曲率 | 几米（几十 km 路线） | 否（相对大小不变） |

**关键结论**：我们要的不是"距离精确到厘米"，而是"哪家 POI 最顺路"。建模近似对所有候选 POI 是同比例的，**相对大小关系不变 → 排序稳定**。所以用 double 平面欧氏近似足够，不需要 Haversine 球面公式或 BigDecimal。

单测里用 `isCloseTo(预期, within(2.0))` 而非精确等于，正是给上述建模近似预留容差。

## 7. 与代码的对应关系

| 数学概念 | 代码方法 |
|---|---|
| 经纬度→米换算 | `metersPerLonDegree(a, b)`、`distanceMeters(a, b)` |
| 点到线段距离（投影+钳制） | `pointToSegmentMeters(p, a, b)` |
| 点到折线最近距离 | `minDistanceMeters(poi, route)` |
| 累计弧长 + 线性插值采样 | `sampleRoute(route, intervalMeters)` |
| 采样点去重 | `addSample(...)` 里的 `DEDUP_EPSILON_METERS` |
