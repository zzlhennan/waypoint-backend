# 「沿途」需求文档（PRD v1.3）

> 阶段：需求分析 ✅ 已完成
> 状态：需求基线已锁定，进入编码阶段
> 本文件为**唯一事实源**，存放于 `waypoint-backend/docs/`。

---

## 1. 背景

独立开发者的第一个项目。起点：每天骑车上下班想买咖啡，但不知道哪家店在路线上"不绕路"。

**为什么要做这个**：
- 高德/百度的"沿途搜"藏得深、只给列表不排序，用户看不出哪家最顺
- Google Maps 的 "Search along route" 国内用不了
- 我们聚焦一件事：**把"绕路成本"算出来给用户看**

---

## 2. 产品定位（一句话）

**不是导航软件，是"从 A 到 B 路上顺便办件小事"的决策工具。**

- 用户已经知道怎么从 A 到 B（导航交给高德）
- 用户想顺便完成一个小目标（买咖啡 / 加油 / 上厕所）
- 我们帮用户找出**最不绕路**的那一家

---

| 角色 | 描述 | 当前阶段 |
|---|---|---|
| **自己（开发者）** | 骑车上下班的通勤者 | ✅ 第一波真实用户 |

## 4. 用户故事

### US-1（MVP 必做）：通勤买咖啡

> 作为一名**骑车上下班的人**，
> 我想**输入家和公司的位置，看到沿途有哪几家咖啡店、每家要绕多少米**，
> 以便**选一家最顺路的，不用每次都打开高德搜索再心算绕路**。

**验收标准**：
- ✅ 输入城市、起点地名、终点地名、关键词（"咖啡"），**10 秒内**出结果
- ✅ 返回最多 3 家店，按绕路距离**从近到远**排序
- ✅ 每条结果显示：店名、地址、绕路距离（米）、坐标
- ✅ 找不到结果时，明确提示"沿途 1 公里内没找到 XX"，而不是返回空列表假装成功

### US-2（待排期）：开车找加油站
关键词换成"加油站"，算法复用，MVP 不做测试。

### US-3（更远期）：跑步找厕所 / 贩卖机
同上，换关键词。

## 5. 功能范围（MVP）

### 做什么

| 功能 | 说明 |
|---|---|
| F-1 输入起点 / 终点 | 地名（如"奥森公园"）+ **必填城市**，后端用关键字搜索 POI 定位 |
| F-2 输入需求关键词 | 接口参数 `keyword`，MVP 只保证"咖啡"调通 |
| F-3 计算沿途 POI 列表 | 沿路线每 500m 采样，每采样点附近 500m 搜 POI |
| F-4 采样点搜不到时的兜底 | 单采样点 500m 无结果 → 扩到 1km 重试**一次** |
| F-5 绕路距离排序 | 按 POI 到主路的最近直线距离升序 |
| F-6 防御性硬过滤 | POI 离主路 > 1km 直接丢弃（兜底） |
| F-7 返回 Top 3 | JSON 接口，Postman 自测 |

### 明确不做（Non-Goals）

- ❌ 地图可视化 / 路线画在图上
- ❌ 导航 / 转弯指引
- ❌ 用户注册、登录、历史记录
- ❌ 评论、评分、收藏
- ❌ 路线编辑器（中途加点、绕行设置）
- ❌ 前端页面（Postman 阶段不算前端）
- ❌ 多关键词同时搜
- ❌ POI 营业状态判断
- ❌ 并发调用高德 API（MVP 串行，接受 5-10s）

## 7. 算法口径（最终版）

```
入参：city, start, end, keyword (+可选 mode/topN/radius/types/strategy)
   │
   ├─① 关键字搜索 POI 定位起点终点（v5 place/text，region=城市&city_limit=true，取 pois[0].location）
   │     接口细节见 docs/02-高德API.md
   │     （⚠️ 不用 geocode——对"奥森公园"等简称报 30001，已实测）
   │
   ├─② 路径规划（v5，按 mode 选 driving/walking/bicycling）：
   │     A、B 坐标 → 路径坐标串 List<Point>
   │     （必须传 show_fields=polyline，默认 steps 无坐标）
   │
   ├─③ 沿路径采样：**起点 + 每 500m 一个中间点 + 终点**（起终点强制包含——
   │     起点/终点是用户必然在的位置，那里的店"零绕路"，漏掉就违背"顺路"初衷；
   │     沿折线累计长度 + 段内插值，见 03 DetourCalculator）
   │
   ├─④ 对每个采样点独立判断：
   │     先按 500m 半径搜 POI，无结果则自动扩到 1km 重试一次
   │     （不无限扩大，不影响其他采样点）
   │
   ├─④.5 合并所有候选 POI，按 POI id 去重
   │     （采样间隔 500m + 搜索半径 500m，相邻采样圈大面积重叠，同店会被重复搜到）
   │
   ├─⑤ 对去重后的 POI，算到主路折线的最近直线距离 distanceToRouteMeters
   │     口径：欧氏近似——经纬度先转米（纬度×111000、经度×111000×cos纬度），再算平面距离
   │     ⚠️ 不是高德 around 返回的 distance（那是 POI 到采样点的距离，弃用）
   │
   ├─⑥ 硬过滤：离主路 > 1km 的 POI 直接丢弃（防御性，理论上不触发）
   │
   └─⑦ 按 distanceToRouteMeters 升序排序，取 Top N（默认 topN=3）；过滤后为空 → 返回 404
```

**⚠️ 两个 distance 别混**：
- 高德 around 返回的 `distance` = POI 到**采样点**的距离（高德算的，我们**不用**）
- 我们响应的 `distanceToRouteMeters` = POI 到**整条路线折线**的最近距离（DetourCalculator 自算）

**关键配置（application.yml，不硬编码）**：
```yaml
along:
  sample-interval-meters: 500
  search-radius-meters: 500
  search-radius-retry-meters: 1000
  max-detour-meters: 1000
  top-n: 3
```

## 8. 成功标准

**MVP 成功 = 开发者本人每天骑车上下班都愿意用，并且觉得"比打开高德搜咖啡方便"。**

量化指标（先记着）：
- 一次查询响应 < 10 秒（MVP 容忍度）
- 返回结果中 ≥ 1 家真的"顺路"（绕路 < 300 米）
- 自己连续用 5 天以上

## 9. 已拍板的决策记录

| 问题 | 决策 | 备注 |
|---|---|---|
| Q1 重名地点 | 接口加 `city` 参数必填 | 定位时锁定城市 |
| Q2 搜不到 POI | 单采样点独立扩到 1km 重试一次 | 不无限扩大 |
| Q3 最大绕路阈值 | 业务上不需要，改防御性硬过滤 1km | 开发者指出原方案冗余 |
| Q4 关键词 | 接口接受任意 keyword，只对"咖啡"测试 | 算法与关键词解耦 |
| Q5 响应时间 | MVP 串行调用，接受 5-10s | 不提前上并发 |
| Q6 起点终点定位方式 | **place/text 关键字搜索**，不用 geocode | geocode 实测对"奥森公园"报 30001 |
| Q7 外部 HTTP 调用方式 | **Feign（OpenFeign）** | 开发者选定声明式；mapper 持久层 MVP 留空不引框架 |
| Q8 接口可选参数 | 加 `mode`/`topN`/`radius`/`types`/`strategy` 五个可选参数，均有默认值 | 利用高德能力且不破坏 MVP 极简；mode/topN/radius 优先实现，types/strategy 第二步 |
| Q9 高德接口版本 | **全站统一 v5 2.0**（place/text、around、direction） | 定位/周边共用搜索DTO、路径共用路径DTO，仅2个响应DTO；v3仅历史参考 |
| Q10 采样点是否含起终点 | **强制包含起点和终点**（起点 + 每500m中间点 + 终点） | 起终点是用户必然在的位置，那里的店"零绕路"，漏掉就违背"顺路"初衷 |
